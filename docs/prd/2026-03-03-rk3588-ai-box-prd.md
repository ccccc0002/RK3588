# RK3588 AI盒子 Architect 拆分方案（需求拆分 + 整体结构设计）

## 简要总结
本方案按“单盒子可落地 + 二期集群可扩展”做架构拆分。  
核心策略是把系统拆成 4 层：`接入媒体层`、`AI执行层`、`业务控制层`、`平台管理层`，并在一期就预埋 `tenant/site/box` 多级模型和边缘 Agent 接口，避免二期重构。

---

## 1. 架构目标与设计原则

1. 目标
1. 打通 IPC 接入 -> AI分析 -> 告警推送 -> 可视化管理闭环。
2. 满足实时与带宽目标：3秒告警推送、按需直播断流。
3. 一期本地可离线运行，二期可纳入集群统一管理。

2. 原则
1. 性能敏感路径（解码/预处理/推理）走 C++ + RK 平台能力。
2. 业务敏感路径（权限/配置/推送/管理）走 FastAPI。
3. 控制面与数据面解耦：媒体与AI链路独立于后台管理。
4. 所有模块必须具备可观测、可审计、可回溯。
5. API 与数据模型从第一天支持多盒子扩展字段。

---

## 2. 需求拆分（按业务域）

### 域A：设备接入与媒体预览
1. 设备协议接入：RTSP/RTMP/ONVIF/GB28181。
2. GB28181 注册、心跳、目录、级联。
3. WebRTC 1/4/9/16 分屏预览。
4. 按需直播状态机：无人观看 30 秒断流。

### 域B：AI分析与调度
1. MPP 解码、RGA 预处理、RKNN 推理。
2. 多算法支持：检测、越线、OCR、人脸。
3. 自动抽帧与算力预算调度。
4. 过载降级与恢复策略。

### 域C：事件与推送
1. 统一事件结构标准化。
2. 去重聚合、快照、短视频。
3. WebSocket 与 Webhook（Bearer Token）推送。
4. 推送重试、失败追踪、告警回溯。

### 域D：平台管理
1. 权限管理：RBAC + 数据域隔离。
2. 授权管理：离线License、IPC授权数、到期策略。
3. 网络管理：eth0（运维+IPC接入）、eth1（外联推送）。
4. 算法仓库：目录/版本/状态/示例/UI导入。
5. 底库管理：人脸/工服/PPE/开发底库。
6. 界面设置+i18n+主题。

### 域E：扩展接入
1. 离线视频上传异步分析。
2. HTTP/JPEG 图片流接入。
3. 图片批量分析任务。

### 域F：二期集群预埋
1. Edge Agent：注册、心跳、配置下发、状态回传。
2. 断网自治与恢复补传。
3. 灰度升级与回滚接口。
4. 租户-站点-盒子三级模型。

## 3. 整体结构（逻辑架构）

1. 接入媒体层
1. `wvp-gb-service`：GB28181 信令与级联编排。
2. `zlm-media-service`：流会话与 WebRTC 分发。
3. `device-ingest-service`：RTSP/RTMP/ONVIF 接入管理。
4. `viewer-session-service`：会话心跳、观看计数、按需断流。

2. AI执行层
1. `decode-pipeline`（C++）：MPP 解码。
2. `preprocess-pipeline`（C++）：RGA 预处理。
3. `inference-core`（C++）：RKNN 推理、后处理。
4. `ai-orchestrator`（Python）：动态抽帧、任务编排、资源调度。

3. 业务控制层
1. `api-gateway`（FastAPI）：统一 REST/WS API。
2. `event-center`：事件标准化、去重、告警素材生成。
3. `push-gateway`：Webhook/WS 推送与重试。
4. `offline-analysis-service`：离线视频/图片流任务处理。

4. 平台管理层
1. `auth-service`：账号、RBAC、数据域。
2. `license-service`：离线授权导入、计数与到期拦截。
3. `network-service`：双网口策略、连通性、路由。
4. `algorithm-repo-service`：算法仓库元数据与上架管理。
5. `base-library-service`：四类底库管理与特征索引。
6. `ui-config-service`：品牌、i18n、主题。

5. 数据与基础设施层
1. `PostgreSQL`：配置、事件元数据、权限、审计。
2. `Redis`：会话心跳、队列、限流、短期缓存。
3. `Object Storage(LocalFS)`：告警快照与短视频。
4. `Prometheus/Grafana + Loki`：监控与日志。

## 4. 关键时序设计

### 4.1 实时分析主链路
1. 设备接入 -> 媒体服务建流。
2. 预览请求触发观看会话注册。
3. 码流进入解码/预处理/推理流水线。
4. 事件中心产出告警并落库。
5. 推送网关分发 WebSocket + Webhook。
6. 控制台/小程序实时展示。

### 4.2 按需直播链路
1. 客户端订阅流 -> `viewer_count +1`。
2. 客户端离开 -> `viewer_count -1`。
3. 若计数归零，进入 `IDLE_PENDING` 30秒计时。
4. 计时内有新观看者 -> 回 `ACTIVE`。
5. 超时无观看者 -> `STOPPED` 断流释放资源。
6. 新观看请求 -> `RESUMING`，5秒预热，回 `ACTIVE`。

## 6. 框架选型（最终建议）

1. 媒体与国标
1. `WVP + ZLMediaKit`（满足 GB28181 接入与级联要求）。

2. 解码与推理
1. `MPP + RGA + RKNN Runtime`。
2. C++17 + CMake 构建 `inference-core`。

3. 业务控制
1. Python 3.11 + FastAPI + Pydantic v2。
2. SQLAlchemy + Alembic。
3. Celery + Redis（异步任务）。

4. 前端
1. Vue3 + Vite + TypeScript + ECharts。
2. 微信小程序复用统一 REST + WS。

5. 运维与观测
1. Docker Compose（一期）。
2. Prometheus + Grafana + Loki。
3. 二期迁移 K3s/K8s。

## 7. 分阶段开发计划（按难易与依赖）

### P0（先闭环，6-8周）
1. 设备接入（RTSP/RTMP/ONVIF基础）。
2. WebRTC 单路+1/4分屏。
3. 按需直播状态机。
4. MPP+RGA+RKNN 最小推理链（检测+越线）。
5. 事件中心+WebSocket/Webhook。
6. 基础权限与License控制。
7. 基础驾驶舱与告警页。

### P1（核心增强，5-7周）
1. GB28181 + 级联基础。
2. 9/16分屏。
3. OCR + 人脸识别。
4. 告警短视频。
5. 数据域权限、网络管理、审计日志。
6. 品牌设置+i18n+主题。

### P2（业务扩展，4-6周）
1. 算法仓库完整能力。
2. 四类底库管理。
3. 离线视频分析。
4. HTTP/JPEG 图片流 + 图片批量分析。
5. 小程序闭环。

### P3（二期预埋，3-5周，可并行）
1. Edge Agent。
2. 断网自治补传。
3. 灰度升级回滚接口。
4. tenant/site/box 全链路打通。

## 9. 测试与验收用例（架构级）

1. 高频切屏与观看进出下的断流/重连正确性。
2. 多路输入下动态抽帧收敛与稳定性。
3. Webhook失败重试、死信追踪、幂等验证。
4. License到期和IPC超限拦截一致性。
5. 底库命中回溯到版本与样本ID。
6. 断网自治 + 恢复补传完整性。

---

## 10. 关键假设与默认值

1. 算法 UI 导入后立即生效（当前规则）。
2. IPC 授权按“已启用设备数”计数。
3. 授权到期精确到秒。
4. 仅保存告警快照与短视频。
5. 所有预览流按需直播，30秒断流、5秒预热。
